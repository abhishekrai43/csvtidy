Three ways to combine a folder of CSVs into one file — plain Windows copy, PowerShell, and csvtidy — with the catches of each, honestly. All three run entirely on your machine.

copy *.csv combined.csv # the classic

The one-liner everyone finds first. In CMD, from inside the folder:

cd C:\exports
copy *.csv combined.csv

(Same idea with type *.csv > combined.csv, or on Linux/macOS cat *.csv > combined.csv.) It concatenates the files byte-for-byte — which is exactly its problem. Three catches:

  • Repeated headers. Every file's header line lands in the middle of your data as an ordinary row. Ten files = nine junk rows you must hunt down.
  • No column alignment. If one file has an extra column, or columns in a different order, values silently shift into the wrong columns. Nothing warns you.
  • Mixed encodings and stray bytes. UTF-8 BOMs and different encodings are glued together blindly; the combined file can open as mojibake.

When it's fine: identical, header-less exports from the same system, quick and dirty. It never parses anything, so it's fast at any size — just structurally blind.

PowerShell # Import-Csv | Export-Csv

Get-ChildItem *.csv | ForEach-Object { Import-Csv $_ } | Export-Csv combined.csv -NoTypeInformation

A real improvement: PowerShell parses the CSVs, so headers are handled correctly — one header in the output, none in the middle. Remaining catches:

  • First file wins. The output's columns come from the first file; columns that only appear in later files are dropped without an error.
  • Memory and speed. Every row becomes a .NET object. On hundreds of thousands of rows this gets slow; on multi-gigabyte files, impractical.
  • No cleanup. Duplicates, mixed date formats, and stray whitespace pass straight through — that's a second script.

csvtidy merge # built for exactly this

pip install csvtidy
csvtidy merge C:\exports --output combined.csv --source-column file

One command, structure-aware:

  • Headers handled — read as headers, never repeated as data.
  • Columns aligned by name across files — extra or reordered columns don't shift data; missing cells become empty.
  • Bigger than RAM — DuckDB streams and spills to disk, so folders of multi-gigabyte exports merge on a laptop.
  • Cleanup in the same pass — chain dedupe and date fixes, or save the whole thing as a recipe and re-run it on next month's folder:
csvtidy merge ./exports | csvtidy dedupe - --subset email > clean.csv

FAQ

How do I combine all CSV files in a folder with CMD? cd into the folder, then copy *.csv combined.csv — accepting the repeated-header and column-alignment catches above.

Why does my merged CSV have headers in the middle of the data? Because copy/type/cat concatenate literally — each file's header line becomes a data row. Use a CSV-aware tool (PowerShell or csvtidy) to avoid it.

What if my files have different or reordered columns? copy misaligns silently; PowerShell drops later-file-only columns; csvtidy aligns by name and leaves missing cells empty.

Can I merge files bigger than RAM? With copy, yes but blindly; with PowerShell, not realistically; with csvtidy, yes — DuckDB streams and spills to disk.
